## 2. 变更控制（Change Control）

### 2.1 不可擅自变更的内容

未经用户**明确书面同意**（对话中回复「同意变更」并指明变更项），禁止修改：

- 总计划及规范文档中的：项目目标、模块划分、技术栈选型、版本锁定、架构分层、性能 SLA、里程碑日期、验收标准
- 模块计划中的：核心接口契约、数据模型、Agent 拓扑
- 进度表中的：已完成状态（不得虚假标记完成）

### 2.2 允许 AI 自主微调的内容

- `02_PROGRESS.md` 中「进行中」任务的子任务拆分（不超出模块范围）
- 代码实现细节（命名、目录结构微调），只要不违反总计划
- Bug 修复、测试补充
- 文档错别字

### 2.3 变更申请格式

当必须变更总计划时，AI 须输出 **变更申请（CR）**：

```markdown
## 变更申请 CR-YYYYMMDD-NNN
- **申请人：** AI Agent
- **变更类型：** [范围/技术/进度/验收标准]
- **原内容：**
- **拟变更为：**
- **原因：**
- **影响模块：**
- **状态：** 待用户审批
```

**在用户批准前，不得按新内容执行。**

## 3. AI Agent 工作协议

### 3.1 会话启动

1. 读取 `AGENTS.md`
2. 读取 `01_MASTER_PLAN.md`，确认 `plan_status`
3. 读取 `03_DEV_ENVIRONMENT.md`、`04_ARCHITECTURE_STANDARDS.md`、`05_PERFORMANCE_STANDARDS.md`
4. 读取 `02_PROGRESS.md`，仅执行其中 `status: in_progress` 或用户点名任务
5. 读取对应 `docs/modules/M*.md`

### 3.2 会话结束

- 更新 `02_PROGRESS.md`（完成项、阻塞项、下一步）
- 不修改 `01_MASTER_PLAN.md`（除非用户已批准 CR）

### 3.3 切换 Agent / 模型

新 Agent 视为零上下文，**必须重新执行 3.1**，不得假设记得上次对话。

## 4. 生产级标准（全局约束）

| 维度 | 最低要求 |
|------|----------|
| 代码 | 类型注解、单元测试覆盖率核心模块 ≥ 70% |
| API | OpenAPI 文档、统一错误码、请求 ID 追踪 |
| 安全 | 密钥环境变量注入；敏感数据本地存储；日志脱敏 |
| 部署 | Docker Compose 生产配置；健康检查端点 |
| Agent | 状态持久化、重试、熔断、HITL 人工节点 |
| 文档 | 每个模块 README + ADR（重大技术决策记录） |

## 5. 审核与锁定

| 阶段 | 总计划状态 | 允许操作 |
|------|-----------|----------|
| 起草 | `DRAFT` | 仅讨论、修改计划文档 |
| 用户批准 | `APPROVED` | 按进度表开发 |
| 变更中 | `CHANGE_PENDING` | 等待 CR 审批，暂停相关开发 |
| 冻结 | `FROZEN` | 仅 Bug 修复，不增功能 |

**当前：** `APPROVED` — 按 `02_PROGRESS.md` 执行开发

---

## 6. 用户审批指令

用户审核总计划后，请回复以下之一：

- **「批准总计划」** → 状态改为 `APPROVED`，按 Sprint 1 开工
- **「修改：{具体意见}」** → AI 修订后重新提交审核
- **「驳回」** → 保持 `DRAFT`，重新规划
